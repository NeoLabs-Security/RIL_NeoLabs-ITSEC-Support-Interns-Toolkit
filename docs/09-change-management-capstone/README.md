# Module 9 - Change Management, Handover and Capstone

## Change lifecycle

1. Define the symptom, evidence and proposed change.
2. Identify risk, dependencies, affected users and required downtime.
3. Capture the original state and prepare backup/rollback.
4. Obtain named approval.
5. Implement only the approved steps.
6. Validate service, security controls, logs and user outcome.
7. Roll back if acceptance criteria fail.
8. Communicate completion, limitations and follow-up work.

Emergency changes still require attribution, minimum scope, validation and retrospective review.

## Handover standard

A second technician should be able to understand the asset, problem, evidence, actions, current state, remaining risk and next step without relying on an informal chat.

## Capstone

Interns receive synthetic tickets involving an account problem, endpoint configuration drift, network symptom, vulnerable software and restore request. They must classify each case, collect read-only evidence, separate support from incident work, prepare approved changes, validate results and produce a final handover pack.

## Assessment

Scoring covers diagnosis, evidence, least privilege, approval discipline, rollback quality, security preservation, communication and documentation. Fast closure without understanding or evidence receives low credit.

## Completion standard

A learner can safely receive, diagnose, escalate, remediate, validate and hand over an assigned support case without weakening controls or destroying evidence.
