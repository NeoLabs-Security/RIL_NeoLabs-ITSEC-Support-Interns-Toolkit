# NeoLabs IT Security Support Documentation Index

Use this page as the authoritative learning-material map. Follow `../LEARNING_PATH.md` and `../SUPPORT_BOUNDARIES.md` before making any change to an assigned system.

## Core modules

- `01-secure-support-foundations/` — intake, verification, evidence, diagnosis and escalation
- Windows support/security material — services, Defender, Firewall, BitLocker, updates and logs
- Linux support/security material — users, sudo, SSH, services, firewall, packages and journals
- Networking material — TCP/IP, DNS, DHCP, routing, ports, firewall and TLS diagnosis
- `05-asset-software-identity/` — inventory, lifecycle, account and access operations
- `06-patch-vulnerability-management/` — advisory review, prioritization, change planning and rollback
- `07-backup-recovery-continuity/` — backup integrity, restore testing, RPO and RTO
- `08-incident-intake-escalation/` — recognizing security incidents and handing evidence to SOC
- `09-change-management-capstone/` — controlled changes, validation, rollback and handover

## Practical resources

- `../scripts/` — read-only Windows/Linux baseline collectors and guarded training helpers
- `../labs/` — synthetic diagnosis, recovery and support practice
- `../templates/` — tickets, access reviews, changes, escalation and handover records
- `../troubleshooting/` — common platform, identity, network and recovery problems

Diagnosis is read-only by default. Live changes require the assigned ticket, explicit approval, original-state evidence, a rollback plan and validation.
